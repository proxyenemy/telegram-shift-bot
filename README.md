# Бот лучших смен

Python 3.11 или новее. Внешние библиотеки не нужны. Бот сохраняет подписи к фото и текстовые отчёты в SQLite и отправляет итог по понедельникам в 10:00 по Москве. Неделя — понедельник–воскресенье, дата берётся из подписи. Сравнивается сумма одной смены, а не сумма всех смен сотрудника.

## Настройка

1. Создайте бота через @BotFather и добавьте его администратором группы с правом отправки сообщений.
2. Скопируйте config.example.json в config.json. Заполните chat_id группы, source_topic_id топика с отчётами и target_topic_id топика для итогов.
3. Для ссылки на сообщение вида https://t.me/c/1234567890/123/789: chat_id = -1001234567890, ID топика = 123. Проверяйте ссылки именно на сообщения внутри нужных топиков. Для других видов ссылок эти правила могут отличаться.
4. В people можно указать реальные числовые Telegram ID сотрудников, их имена и username без @. Это нужно для старого экспорта, в котором username автора обычно отсутствует. ID находится в from_id вида user123456789. Без соответствия бот укажет имя и кликабельную ссылку «профиль» по ID. Для новых сообщений username берётся из Telegram.

## Загрузка истории

В Telegram Desktop откройте меню группы → «Экспорт истории чата». Выберите формат JSON, отключите скачивание медиа: нужны только текстовые подписи. Экспортируйте **одну группу**, не весь аккаунт. Для фильтрации топика лучше выгрузить всю текстовую историю: ограниченный экспорт может не содержать цепочки ответов, по которым определяется топик.

В PowerShell перейдите в папку бота и выполните:

```powershell
Copy-Item config.example.json config.json
# Сначала заполните config.json, затем:
python bot.py import --file 'C:\путь\к\result.json'
python bot.py preview
```

По умолчанию импортируется предыдущая календарная неделя. Для другой недели:

```powershell
python bot.py import --file 'C:\путь\к\result.json' --week 2026-10-19
python bot.py preview --week 2026-10-19
```

Повторный импорт обновляет записи, не создавая дубликаты. Сообщения вне нужной недели игнорируются. Топик определяется по message_thread_id или цепочке reply_to_message_id к корню топика. Если экспорт не содержит этих связей, сообщения пропускаются: не следует обходить фильтр, иначе в отчёт попадут чужие топики. Счётчик пропусков и preview позволяют проверить полноту перед запуском.

## Запуск

Откройте local_settings.py рядом с bot.py и вставьте токен от @BotFather между кавычками:

```python
BOT_TOKEN = "ВАШ_ТОКЕН_ОТ_BOTFATHER"
```

Сохраните файл. Он исключён из Git через .gitignore. После этого при каждом запуске достаточно одной команды:

```powershell
python bot.py run
```

Если local_settings.py отсутствует или BOT_TOKEN пустой, можно передать токен через переменную окружения BOT_TOKEN. Токен не публикуйте и не добавляйте в config.json. Процесс должен постоянно работать на компьютере или сервере; для круглосуточной работы настройте автозапуск и перезапуск процесса. Не запускайте две копии с одной базой. Другие программы не должны получать обновления этого же бота; существующий webhook нужно предварительно отключить.

При запуске после понедельника 10:00 бот отправит пропущенный отчёт за предыдущую календарную неделю, если есть хотя бы один отчёт. Поэтому сначала импортируйте данные и проверьте preview. Недели старше предыдущей автоматически не рассылаются. Для полностью пустой недели отправки нет; для дней без данных выводится «Нет отчётов». При равенстве суммы указываются все победители.

## Формат исходного сообщения

```text
29.10
88$
```

Поддерживаются $88, 88$, $44,4 и 44.40$. Дата и сумма должны занимать отдельные строки. Год можно указать как 29.10.2026; без года выбирается ближайшая к дате публикации дата. Изображения не распознаются — сумма читается из подписи. Фотоальбом с общей подписью учитывается один раз.

## Ограничения

Удаление сообщения не поступает обычному боту как обновление, поэтому удалённую смену нужно удалять из базы отдельно. Правки полученных сообщений обрабатываются, но уже опубликованный недельный итог автоматически не исправляется. После изменения username старые записи могут содержать прежний username. Экспорт не даёт автоматического доступа к истории: при первом запуске JSON загружается вручную, далее бот собирает новые сообщения сам.

Отправка и фиксация в SQLite не образуют общую транзакцию: если процесс аварийно завершится после отправки, но до записи результата, возможна повторная публикация. При длительном отключении Telegram хранит необработанные обновления не более 24 часов; пропуски нужно восполнить импортом. Очень большое число победителей может превысить лимит длины Telegram-сообщения — текущая версия рассчитана на небольшую команду.
